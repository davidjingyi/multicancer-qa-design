# 多癌种LLM问答设计思路

## 为什么这么做

我想把现在只回答乳腺癌问题的方式扩展到其他癌种。我不想再围着向量化、Embedding、Chunk 和向量数据库搭一套传统 RAG，而是想让大模型真正参与问答：先弄明白用户在问什么、问的是哪种癌，再结合前面的对话组织回答。

指南 PDF 还是回答的依据，不能脱离原文凭空回答。服务器会按癌种把 PDF 分开，程序只去对应的文件夹里找相关页面，再把这些内容交给模型。目前癌种判断和回答生成由模型负责；PDF 页面仍由本地全文关键词检索来初筛和排序。简单说，就是不再让向量 RAG 当主角，但指南证据和来源还得保留。

网站入口：<https://oncompass.site/>

## 用户问了以后怎么处理

如果用户已经选了癌种，就按这个选择去对应文件夹找 PDF。如果没选，先让大模型从服务器已有的癌种列表里判断，并给出置信度。现在的门槛是 0.55；问题说不清、不是肿瘤指南问题，或者几种癌症分不出主次，就先请用户补充，不往下查。问题里提到的癌种和当前选择对不上时，也会请用户切换癌种或把问题拆开，避免拿错指南。

癌种确认后，只搜对应文件夹，不跨癌种混在一起。程序会根据问题里的中文词组、英文和数字给 PDF 各页打分，最多取 8 页，同一本 PDF 最多取 3 页。这里是全文关键词检索，没有做向量化或人工切块。

普通 PDF 用 `pdftotext` 提取正文。扫描页正文太少时，会先转成图片，再用 Tesseract 做中英文 OCR。提取的文字会按癌种和 PDF 路径缓存，同时记录 PDF 的 SHA-256；PDF 有更新就重新提取，PDF 删除了就清理对应缓存。

找到足够相关的指南内容后，才让大模型生成回答，并附上 PDF 文件名、目录和页码。没找到足够依据，就说明没有检索到足够材料，不继续生成医学结论。

## 一轮会调用几次模型

- 用户预设了癌种：不做分类；找到足够依据后，调用一次回答模型。
- 用户没有预设癌种：先调用一次模型判断癌种，再调用一次模型回答。只有分类通过、而且也找到了足够依据，才会进入回答这一步。
- 癌种判断不确定、癌种对不上，或者没有找到足够依据：不会再调用回答模型。

所以，自动判断并成功回答时通常是两次模型 API 调用；用户预设癌种并成功回答时通常是一次。PDF 文字提取和关键词检索都在服务器本地完成，不会额外调用模型。

## 对话和 API

聊天记录按登录账号和癌种保存在浏览器本地。发消息时只带上最近的一部分对话，也会过滤明显属于其他癌种的内容。用户可以删除历史记录；删除的是当前浏览器保存的那条对话。

网页之外，也提供 OpenAI Chat Completions 风格的接口：

```text
POST https://oncompass.site/v1/chat/completions
Authorization: Bearer <登录令牌或 API Key>
Content-Type: application/json
```

请求用常见的 `model`、`messages`、`stream` 字段，也可以通过 `cancer_id` 预设癌种。回答放在 `choices[0].message.content` 里，同时会返回癌种判断、检索状态和 `sources` 来源。目前支持 `stream: false`，调用接口需要有效身份认证。

## 使用边界

这个问答工具用于健康教育和就医沟通，不能替代医生诊断或治疗建议。回答是否可靠，和癌种目录对应得是否正确、PDF 是否为合适版本、正文能否正常读取都有关系；看到回答后，仍应核对它引用的指南原文。账号密码、模型密钥、患者资料和受版权限制的指南 PDF 不应公开。
